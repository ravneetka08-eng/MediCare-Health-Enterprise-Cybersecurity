# Enterprise Cybersecurity Control Library

## Purpose

This library defines the enterprise cybersecurity controls used
throughout the project.

Each control may be linked to:

- Risk IDs;
- Asset IDs;
- Control Owner;
- Implementation technology;
- Control Tests;
- Evidence;
- Findings;
- Framework mappings;
- Exceptions.

---

# Control Record Fields

Each material control should contain:

| Field | Description |
|---|---|
| Control ID | Unique identifier |
| Control Name | Short control title |
| Domain | Security control domain |
| Objective | Security outcome |
| Requirement | What must occur |
| Control Type | Preventive / Detective / Corrective / Recovery / Directive |
| Risk IDs | Risks treated by the control |
| Assets | Applicable assets |
| Control Owner | Accountable function |
| Operator | Function performing routine activity |
| Frequency | Continuous / Daily / Monthly / etc. |
| Technology | Technology supporting implementation |
| Implementation Status | Current state |
| Design Effectiveness | Assessment |
| Operating Effectiveness | Assessment |
| Test ID | Associated assurance test |
| Evidence | Supporting evidence |
| Exception | Approved deviation if applicable |

# IAM — Identity and Access Management

## CTRL-IAM-001 — Unique Workforce Identities

**Objective**

Ensure workforce activity can be attributed to individual authorised
identities.

**Requirement**

Each workforce user must receive an individually assigned identity.

Shared interactive user accounts should not be used unless a
documented operational requirement and approved exception exists.

**Type**

Preventive / Accountability

**Related Risks**

- R-001
- R-002
- R-005
- R-006
- R-010

**Control Owner**

Identity and Access Management

**Technology**

Active Directory / AWS IAM where applicable

**Project Implementation**

Representative users will receive separate Active Directory accounts.

Examples:

- reception.user
- clinician.user
- soc.analyst
- it.user

**Status**

Planned

**Operating Effectiveness**

Not Tested

---

## CTRL-IAM-002 — Role-Based Access Control

**Objective**

Ensure users receive access appropriate to their organisational role.

**Requirement**

Access must be assigned through approved role-based security groups
where technically appropriate.

**Related Risks**

- R-002
- R-005

**Control Owner**

IAM with Business / Application Owners

**Technology**

Active Directory Security Groups

**Project Implementation**

Representative groups will include:

- GG-Reception-Users
- GG-Clinical-Users
- GG-SOC-Analysts
- GG-IT-Admins

**Validation**

Positive and negative access tests will be performed.

**Status**

Planned

**Operating Effectiveness**

Not Tested

---

## CTRL-IAM-003 — Least Privilege

**Objective**

Restrict user access to the minimum permissions required for their
role.

**Requirement**

Standard workforce users must not receive unnecessary administrative
or restricted-resource access.

**Related Risks**

- R-001
- R-002
- R-005
- R-010

**Validation**

A Reception user will be tested against:

1. authorised Reception resource;
2. restricted Clinical resource;
3. administrative operation.

Expected:

Authorised resource = Allowed

Restricted resource = Denied

Administrative operation = Denied

**Status**

Planned

---

## CTRL-IAM-004 — Account Lifecycle Management

**Objective**

Ensure identities are created, changed and disabled according to
workforce status.

**Requirement**

Joiner, Mover and Leaver events must trigger appropriate identity
changes.

**Related Risks**

- R-006
- R-001

**Project Test**

A representative former workforce identity will be disabled and an
authentication attempt performed.

Expected result:

Authentication rejected.

**Status**

Planned

# PAM — Privileged Access

## CTRL-PAM-001 — Privileged Account Separation

**Objective**

Reduce exposure created by routine use of administrative credentials.

**Requirement**

Personnel requiring administrative access should use separate
standard and privileged identities.

Example:

Standard:

it.user

Privileged:

it.admin

**Related Risks**

- R-001
- R-010

**Technology**

Active Directory

**Project Validation**

Verify the standard identity cannot perform the selected
administrative operation while the authorised privileged identity can.

**Status**

Planned
